# 決定の記録

日付つきの決定ログ。決定、理由、影響を短く書く。覆すときは新しい項目を足し、古い項目は消さずに「→ YYYY-MM-DD に変更」と添える。

## 2026-10-10

### コンセプトから作り直す

- **決定**: プロトタイプ（bash、`notes/prototype/`）を捨て、コンセプトから設計し直す。プロトタイプは参考資料としてだけ残す
- **理由**: 試用で見やすさと導入の手軽さは評価されたが、制限を足しては外す迷走でシンプルさを失っていた。残った制限の多くは「将来の使い方の予測」を守るものだった
- **影響**: 新リポジトリ `~/dev/lsboard`。[principles.md](principles.md) の「制約には 2 種類ある」が、この経験から来た判断基準

### step / repo / task / role を外す

- **決定**: ワークフローの段階（step）、リポジトリ（repo キー、`.forges/` `.repos/`）、task、role を持たない。残すのは任意の `name` と `message` だけ
- **理由**: 見たいのは「AI が今どういう状態か」で、作業がどの段階かではない。プロトタイプの複雑さ（hash 計算、root だけが step を進める規則、lint の大半）はほぼ全部この側から来ていた
- **影響**: 規約が半分以下になった。段階の管理が要るなら orkestrado 側で行う

### 起こす仕組みを中核にし、デーモンを許可する

- **決定**: `wait` と `watch` を中核機能にする。常駐するプロセスがあってもよい。ただし正本は持たない
- **理由**: 試用で一番困ったのが「子が idle になったことを親に知らせる手段がない」こと。これが解けると conductor のトークン消費に直接効く
- **影響**: プロトタイプの「デーモンなし」から転換。`wait` はブロッキングで、Claude Code のバックグラウンド Bash と組み合わせると待機中のトークンがゼロになる

### entry を空ファイルにし、ファイル名を正本にする

- **決定**: entry は空ファイル。status、sid、agent、name、message はすべてファイル名に持つ。ファイル名に出さない付随情報は `.sids/<sid>/` の小さなファイルに置く
- **理由**: step などを外したことでファイル名に収まるようになった。本文を持たなければ read-modify-write の競合が消え、更新は rename 1 回で済む
- **影響**: プロトタイプの「本文が正本、ファイル名は表示用」という二重構造を廃止。hook が数ミリ秒で終わる

### definitions ディレクトリを持たない

- **決定**: プロトタイプの `.status/` `.steps/` のような、使える値を空ファイルで定義する仕組みを持たない
- **理由**: status は 5 つに固定し、バイナリが知っている。step は外した
- **影響**: board は `.lsboard` `.sids/` `.ended/` と entry だけ

### Rust を選ぶ

- **決定**: 参考実装は Rust の単一バイナリ。依存は clap、serde、serde_json、notify、sha2 に絞り、非同期ランタイムは入れない
- **理由**: この道具の本体は「hook のイベントから status への遷移表」で、enum と網羅的 match が品質に直接効く。Go が勝るのはクロスビルドの手軽さと斜め読みのしやすさで、v1 のローカル運用では顕在化しない。作者の興味も継続のうえで実質的な利点
- **影響**: Linux（docker / VM）向けは musl ターゲットを GitHub Actions でビルドする。bash + jq より hook が速い

### Claude Code を最初の対象にし、他はアダプタで足す

- **決定**: v1 の hook は Claude Code だけ。Copilot CLI、agy、Codex、Gemini は [adapters.md](adapters.md) の手順で後から足す。agy は手間が大きいので優先しない
- **理由**: 主な利用者が Claude Code で、プロトタイプで実機の事実が一番そろっている。無理に広げるより、追加しやすい形を整えるほうが先
- **影響**: `src/hooks/<agent>.rs` を 1 つ足し、`run` に登録方法を足せば追加できる構成

### herdr に依存しない

- **決定**: `name` は任意の文字列として持つだけで、ターミナルのマルチプレクサ（herdr）との対応付けは lsboard の外に置く
- **理由**: 汎用性。コアになるエージェントが直接使う形のほうが、特定の周辺ツールに縛られない
- **影響**: 対応付けが要るなら orkestrado 側で `name` と herdr のエージェント名を結ぶ

### Stop で `30-background` も `40-idle` に戻す

- **決定**: Stop の hook で `background_tasks` に実行中のものがなければ、`20-working` だけでなく `30-background` も `40-idle` にする
- **理由**: 裏の処理が終わったあとの Stop では idle が正しい状態。コンセプト案は `20-working` → `40-idle` だけを書いていたが、それだと background が残り続ける
- **影響**: 実装時の逸脱として記録。テストあり

### SessionEnd は `prompt_input_exit` と `logout` だけ自分を終わらせる

- **決定**: SessionEnd の hook で自分の entry を終わらせるのは `reason` がこの 2 つのときだけ。それ以外は mtime の更新にとどめ、hook が作ったサブエージェントの子はどの理由でも終わらせる
- **理由**: `/clear` などセッションが続く理由で entry を消すと、以後の hook がすべて空振りする。本当の終了は `lsboard run` の後始末が拾うので、hook 側は迷ったら終わらせない
- **影響**: コンセプト案（`clear` 以外は終わらせる）から変更。レビューの指摘による

### `run --agent` で種類を上書きできるようにする

- **決定**: `lsboard run --agent claude -- ./wrapper` のように、コマンド名と違うアダプタを選べる。`name` の既定はコマンド名のまま
- **理由**: ラッパースクリプト経由の起動で hook が黙って登録されないのを防ぐ。アダプタのないエージェントを `--no-hooks` なしで起動したときは stderr に注意を出す
- **影響**: 小さな追加。ラッパーの名前が `ls` で区別できる

### 古いロックを自動で解除しない

- **決定**: ロックの取得時に、古いロックを消して取り直すことはしない。lint が 60 秒より古いロックを報告し、人が消す
- **理由**: 「古い」と判断した 2 つのプロセスが同時に消して作り直すと、両方がロックを持ってしまう。hook はロックを数ミリ秒しか持たないので、古いロックは異常であり、自動回復より報告が適切
- **影響**: `lsboard end` はロックが取れなければ終了コード 1 で失敗し、`run` の後始末は残した entry のパスを stderr に出す

### takuyayukat で公開し、あとで allpaqa-org へ移す

- **決定**: リポジトリは `github.com/takuyayukat/lsboard` に置く。allpaqa-org（OSS を意識したものの置き場）への移管は、2 つ目のアダプタが入るか、自分以外から issue か star が来たかの早いほうで判断する
- **理由**: GitHub のリポジトリ転送はリダイレクトつきで可逆。不可逆なのは名前の確保だけで、個人で公開すれば足りる。v1 は Claude Code だけ、README は日本語、実機確認も途中で、OSS として見せる段階ではない
- **影響**: `Cargo.toml` の `repository` は現在の場所。移管時に書き換える

### crates.io には動く 0.1 ができるまで出さない

- **決定**: 名前を押さえるための空のクレートは公開しない
- **理由**: 空のクレートでの予約は嫌われる。出すなら動くものを出す
- **影響**: 名前の衝突リスクは GitHub 上の公開で下げる。crates.io、PyPI、npm、Homebrew、GitHub のユーザー名はいずれも 2026-10-10 時点で未使用だった
